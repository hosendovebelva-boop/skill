## 硬约束：文字承载方式（最先读，优先于本文件其余所有规则）

**问题从来不是「图里字多」，是「图里有成段的句子」。**

`references/` 七张全部是可读的，其中 `SLO`（64 个 text / 1170 字）、`write 调用者`（64）、`GC 写放大`（62）和 `p99`（61 / 935）字最多，也照样能读。它们和「读不动的图」的区别不在字数，在于**每个 `<text>` 装的是标签还是句子**：

| 参考图 | text 数 | 正文区每条中位 | p90 |
|---|---|---|---|
| readahead | 38 | 8.5 | 26 |
| 全路径 read | 39 | 13 | 22 |
| p99 毛刺 | 61 | 16 | 32 |
| SLO 门禁 | 64 | 14 | 32 |
| write 调用者 | 64 | 16.5 | 37 |
| GC 写放大 | 62 | **3** | 26 |
| SSD 稳态曲线 | 31 | 13 | 36 |

**中位数全在 3–16 字之间。** 一条 text 就是一个标签、一个判据、一个单元格，不是一句完整的话。64 条这样的短标签排进表格和曲线里，眼睛是扫的；15 条 45 字的句子横铺在图上，眼睛得逐行读，那就不该是图。

`GC 写放大` 的中位是 3，因为它 62 条 text 里有一半是页矩阵里的「有效」「失效」「搬入」这种两字格标。**这不是「字更少更好」的证据，是「几何本身在讲话」的证据**——u = 8/16 是被 16 个色块直接画出来的，不是写出来的。能这么画的时候就这么画。

### 四条红线

| 项 | 上限 | 为什么 |
|---|---|---|
| **正文区每条 `<text>` 字数** | **中位 ≤ 20，p90 ≤ 42** | 最重要的一条。超了说明节点里在写句子 |
| **正文区单条 `<text>`** | **≤ 48 字** | 再长就是正文段落，搬走 |
| 字号下限 | **≥ 9.5** | 6 字以内的点状标注（数据点、刻度）可更小 |
| viewBox 高度 | **≤ 900** | 参考图最高 892 |

**「正文区」不含顶部标题副标题、底部口径条、以及 `A · ` / `B · ` 这类区标题。** 这三处本来就是横跨整幅的整行句子，不挤在任何方框里，眼睛一行扫过去，不构成阅读负担。参考图这三处都有 40–52 字的长句。

**没有 text 数量上限，也没有总字数上限。** 只要每条都是短标签、字号够、排进了表格或泳道这类结构里，60 条也可以（SLO 就是 64 条）。

### 字号

| 用途 | font-size | 参考图用法 |
|---|---|---|
| 主标题 | 22 | 左对齐 `x≈48` |
| 副标题 / 区标题 | 13–14 | |
| 节点主标签 | 11.5–13 | 参考图最常用的一档 |
| 表格单元格 / 次要注释 | 10–11.5 | SLO 有 851 字在这一档，仍可读 |
| 点状标注（≤ 6 字） | 9–9.5 | 曲线上的数据点、刻度数字 |

10、10.5、11.5 是参考图的主力字号，**不禁用**。SLO 有 73% 的字落在 11 以下，依然是七张里信息量最大且能读的一张。

### 判据：这条 text 是标签还是句子

写完每条 text 问一句：**它能不能当表头、图例、或者流程里的一个格子？**

- 能 → 留在图里（「同步预读 0–7」「窗口 ×2，并埋下标记页」「关任一 fd，本进程的锁全丢」）
- 不能，它是在解释因果 → 搬进正文（「缺页处理程序发现这是 COW 页而不是真的越权，于是分配新页、拷贝内容、把子进程的页表项改回可写」）

### 反方向也是错的：不要把图掏空

红线是防「把段落搬进图」，不是叫你少画。参考图正文区有 30–56 条标签，靠的是**把长句拆成短标签再排进结构**，不是把内容删掉：

- ✗ 一条 45 字的句子横在图上
- ✗ 删掉这条，图里只剩三个框
- ✓ 拆成表格的一行：`触发条件 | 后果 | 对策` 三个单元格，每格 6–12 字

一张只有 10 条标签、大片留白的图，信息量还不如一段正文，等于白画。**判断标准是「结构讲清楚了没有」，不是「字够不够少」。** 想加内容时先问能不能变成表格行、泳道格、时间条上的一段，而不是先问要不要删。

### 拆图判据

按**叙事单元**拆，不是按字数拆。`p99` 一张图里放了时间线 + 指纹表 + 分层梯 + 放大器四块，因为它们回答的是同一个问题的四个步骤，拆开反而断了链条。

- 四块内容服务同一个问题 → 一张图，用 ①②③④ 串起来
- 两块内容是两个独立的问题 → 两张图
- 判断标准：**缩到 900px 后，最小的字能不能扫读**（不是「一眼读完」，是「能扫」）

### 参考图的用法

七张都是合格范本，按内容形态选：

- `readahead` — 机制帧序列，字最少、几何最多（非文字/文字比 1.26），机制类首选
- `全路径 read` — 跨层泳道 + 编号步骤 + 底部延迟预算条
- `p99 毛刺` — 多手法拼一页：折线 + 表 + 分层梯 + 流程条，诊断/方法类首选
- `SLO 门禁` — 双面板 + 曲线 + 分布重叠 + 对策表，契约/对照类首选
- `write 调用者` — 分层调用链，两条入口汇合于一个门，「谁调用谁」类首选
- `GC 写放大` — 几何直接承载变量 + 逐行算账面板 + 小函数图，**公式推导类首选**
- `SSD 稳态曲线` — 单曲线分段 + 拐点归因 + 预处理流程条，**性能状态/方法论类首选**

**要学的是它们怎么把长句拆成短标签塞进结构里**，不是学它们的字数上下限。

### 交付前自查（必跑）

```bash
python3 ~/.claude/skills/obsidian-svg/scripts/check_density.py 图片/SVG/你的图.svg
```

四项红线任一超标即退出码 1 并指出超了多少。**主要看「每条 text 的字数」那两项**：超标说明在图里写句子了，把那几条搬进正文，不是缩字号也不是整张拆掉。

参考图跑这个脚本用来校准手感：

```bash
python3 ~/.claude/skills/obsidian-svg/scripts/check_density.py ~/.claude/skills/obsidian-svg/references/*.svg
```

七张里五张全绿。两个例外都不是真超标，而是同一个已知边界：

- `write调用者` 两条挂在 Panel A 底边的「读法 / 收口」长句被判超 48 字；
- `GC 写放大` 一条 `y=656` 的 OP 公式条（距底 104px）被判超 48 字。

脚本只豁免整页顶部 100px 与底部 90px，识别不出**面板内部的口径条**、以及**贴在底部区块上方的整幅公式条**。判据是位置不是长度：**不挤在任何方框里、横跨整块或整幅的一行口径句可以留**，节点方框里的句子不行。

| 有公式要推（WAF、队列深度、命中率）、参数怎么影响结果 | 几何画出变量本身 + 逐行算账面板 + 小函数图打 3 个点 | GC 写放大 |

**搭配原则：**

1. **一张图可混用**多种手法（例如上半泳道 + 下半签名表；左曲线 + 右告警表）。
2. **先叙事后装饰**——标题讲清「这张图解决什么问题」，副标题给一句判断准则。
3. **密度服务于教学**——关键数字、公式、边界条件写进图，但受顶部三条红线约束：装不下就拆图，不是缩字号。判断句写正文，图里只放结构。
4. **不要机械复刻**某一张参考的分区数量；参考的是视觉系统与信息架构，不是像素模板。

## 介质路由

在动手之前先决定用 SVG 还是 Mermaid。

**用 SVG：** 静态架构图、机制原理图、内存布局、组件分组、并列对比、概念图、算法概览、技术图表、研究级精绘、诊断全景、泳道、控制环。

**用 Mermaid：** 纯序列图、线程调用链、回调顺序、请求-响应时序、启动/关闭流程、生命周期时间线——且用户未要求 SVG 时。

用户明确要求 SVG、或需要与 vault 教学图同一视觉系统时，**优先 SVG**。

## 工作流

1. **读笔记上下文** — 确定教学点、嵌入位置、是否已有同章参考图。
2. **选型** — 按上表选 1 种主布局，必要时组合副布局；打开 1–2 张 `references/` 对照。
3. **规划几何** — viewBox（宽固定 `1240`，高 **≤ 700**；内容更多就拆成多张，见顶部硬约束）、分区 A/B、坐标网格、标题区高度。
4. **构建 SVG** — 绝对坐标；标签不溢出；中文解释 + 英文标识符。
5. **应用教学视觉系统**（见下）— 与参考图一致，而非只套 strict palette。
6. **保存** — `<vault>/图片/SVG/`，优先数字下划线命名；既有语义文件名可保留。
7. **嵌入** — `![[图片/SVG/<file>.svg|900]]`（宽度可按笔记调整）。
8. **检查** — 合法 XML、背景、可读性；`validate_svg.py` 对教学色板可能失败，见「验证策略」。
9. **diff** — 只动目标 SVG 与必要的笔记嵌入行。

## 教学视觉系统（高性能存储 / 系统笔记首选）

与 `references/SLO-错误预算与噪声回归门禁.svg` 等同族。用于深度教学图；**可与下方「strict 节点色板」并存**：简单卡片图用 strict，教学全景用本系统。

### 画布与字体

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1240 H"
     font-family="'PingFang SC','Hiragino Sans GB','Microsoft YaHei','Noto Sans CJK SC',sans-serif">
```

- 背景：`fill="rgb(245, 244, 237)"` 或 `#F5F4ED`，铺满 viewBox
- 面板底：`#FBFBF6`，描边 `#D8D5C8`
- 主标题：`font-size="22" font-weight="700" fill="#2B2A26"`，**左对齐**（`x≈48`）
- 副标题：`font-size="14" fill="#6B675C"`
- 区标题：`font-size="15" font-weight="700" fill="#4A473F"`，可用 `A · …` / `B · …`
- 节点主标签：`13–14`；副标签与注释：`12`；绝对下限 `11`（全图 ≤ 5 处）
- 中性字色：`#2B2A26` / `#4A473F` / `#6B675C`

### 语义色（节点 / 强调）

| 角色 | fill | stroke | text |
|------|------|--------|------|
| 信息 / 流程蓝 | `#E3EAF4` | `#3D5A80` | `#2C4460` |
| 安全 / 通过绿 | `#DCE9E3` | `#2F6B5E` | `#24473F` |
| 注意 / 窗口琥珀 | `#EFE7DA` 或 `#F3E8D3` | `#8A6A3A` / `#B07D2B` | `#6B4E28` |
| 告警 / 饱和红 | `#F0E0DB` | `#A64B3C` | `#733428` |
| 中性灰 | `#F1EFE8` / `#EDEBE3` | `#4A473F` / `#9B968A` | `#4A473F` |
| 泳道淡紫（可选） | `#EDEAF3` | `#D8D5C8` | `#6B5B95` |

描边宽度：内容框常用 `1.2–1.5`（教学图可读优先）；圆角 `rx="7"` 或 `8`。

### 箭头

教学图优先**实心三角**（与参考一致）：

```xml
<defs>
  <marker id="arr" viewBox="0 0 10 10" refX="8.5" refY="5"
          markerWidth="7" markerHeight="7" orient="auto-start-reverse">
    <path d="M0,0 L10,5 L0,10 z" fill="#5A564B"/>
  </marker>
  <!-- 告警流可用 fill="#A64B3C" 的第二 marker -->
</defs>
```

连线：`stroke="#5A564B"`，`stroke-width="1.5–1.8"`，`marker-end="url(#arr)"`。

### 信息架构习惯

- 顶部：一句「问题/命题」标题 + 一句「判断准则」副标题
- 中部分区：A/B（或 ①②③④）按叙事推进，不是装饰分栏
- 曲线/表/签名卡：只承载决策信息
- 底部：边界条件、口径提醒、或「刻画→对号→二分→验证」类流程条
- 需要公式时用独立条带（如 Little's law / Q_fio），勿塞进过小卡片

特殊值 `none`、`context-stroke`、`currentColor`、`transparent`、`inherit` 允许。

### Strict 排版与间距

- 主标签：`font-family="system-ui,sans-serif" font-size="14" font-weight="500"`
- 副标签：`font-size="12" font-weight="400"`
- 每个 `<text>` 建议含 `dominant-baseline="central"`（教学图若用 `y` 基线排版可省略，但勿混用到难以阅读）
- 框：`rx="8"`，`stroke-width="0.5"`；箭头描边 `1.5`
- 框间距 ≥ 60px；viewBox 底边距 ≥ 40；四周 ≥ 20

        stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"/>

## 语言

- 可见解释性标签默认**中文**
- 代码标识符、API、类名、函数名、文件名、协议名、指标名保持原始语言（`iostat`、`await`、`MESI`、`O_DIRECT` 等）

## SVG 构建规则

- 完整 `<svg>`：`xmlns`、建议设 `width`/`height` 或仅 `viewBox`
- 背景矩形紧跟在 `<defs>` / `<title>` / `<desc>` 之后
- 复杂图加 `<title>` 与 `<desc>`
- 标签在框内；框不够就加大，不缩小到难读
- 长解释放注释栏/底栏，不堆进节点
- 优先正交连线；绝对坐标
- 避免重阴影、复杂渐变、噪点、emoji 装饰

## 科学精度

适用于研究级图表、内存布局、字节单元、时间线、层级结构：

- 可复现几何，共享对齐线
- 重复组件用稳定网格
- 轴、单位、图例、数据编码写清楚
- 文字度量不可靠：给 padding，不赌字体宽度

## 数字下划线命名

从笔记路径数字前缀派生，附加 1-based SVG 索引。

规则：
- 剥离前导零：`04.Linux…` → `4`
- 数字间 `_`；SVG 序号在最后
- 推不出数字前缀时不编造（可保留语义名，如参考图）

示例：
- `8.高性能存储/9.…/9.2 iostat….md` 第 1 图 → `8_9_9_2_1.svg`
- `6.项目/03.远控…/1.2 ….md` 第 2 图 → `6_3_1_2_2.svg`

## 验证策略

1. **结构**：合法 XML；背景存在；嵌入路径正确。
2. **教学图**（本系统色板 + 密排）：以参考图观感为准；`validate_svg.py` 可能因 palette/间距报红——**可接受**，与 `SLO-错误预算与噪声回归门禁.svg` 同策略。
